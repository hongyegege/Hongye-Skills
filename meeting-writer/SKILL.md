# Meeting Writer — 会议纪要生成

将原始会议讨论内容整理为标准格式会议纪要，并创建为飞书文档保存到「会议纪要」文件夹。

## 工作流程

1. **提取用户输入的会议信息** — 从原始内容中提取关键要素
2. **按标准框架重组** — 将讨论内容按议题分层整理
3. **创建飞书文档** — 使用 `feishu_create_doc` 创建文档到「会议纪要」文件夹（folder_token: `XBJxfq1OYlVUzAddlVAcYmd2nzK`）
4. **返回文档链接** — 回复中必须附带飞书文档链接

### ⚠️ 禁止生成的内容
- **不要生成**密级标识（如 □绝密 □机密 □秘密 内部公开）
- **不要生成**纪要编号
- **不要生成**会议标题（文档标题由 feishu_create_doc 的 title 参数控制，正文不需要重复）
- **不要生成**「元信息表」标题（但元信息表本身需要保留，置顶放在文档最上方）
- **不要生成**📍 决策 区块（每个议题结尾不添加决策块）

## 整理规则

### 核心原则

1. **按议题维度组织，不按发言人流水账** — 同一议题下交叉引用各方观点，而非"张三说了什么→李四说了什么"的线性罗列
2. **竞对分析压缩为背景** — 竞对信息做铺垫即可，核心篇幅留给战略与行动
3. **信息缺失时留空** — 不编造任何未提供的信息
4. **发言人排序逻辑** — 领导决策优先 → 技术补充次之 → 认知反馈/局限最后

### 议题拆分

- 每个独立话题作为一个议题
- 议题标题用简洁名词短语，如「暖通业务战略规划框架评审」
- 会议背景放在「一、主要纪要」标题之下、所有议题之上，作为整个会议的背景概述
- 讨论要点按发言人分组，每条提炼核心观点，保留关键细节但不冗长

### 遗留事项

- 从讨论中提取所有需要后续跟进的待办
- 每条必须包含：问题描述、提出人、责任人、确认人、闭环时间
- 闭环时间未知写「待定」

### 语言风格

- 正式、干练、少修饰词
- 保留原文中的专业术语（如 MVP、TMV10、光伏直驱）
- 人名用全名，不缩写
- 决策/结论部分可保留原文中的关键短语（如「讲得通、能落地、能赋能业务」）

## 创建飞书文档

使用 `feishu_create_doc` 创建文档：
- **title**：从用户输入中提取或自拟，如「[会议主题]-会议纪要」
- **folder_token**：`XBJxfq1OYlVUzAddlVAcYmd2nzK`（会议纪要文件夹）
- **markdown**：按上述模板生成的完整内容

创建成功后，回复中**必须附带飞书文档链接**，方便用户直接打开。
