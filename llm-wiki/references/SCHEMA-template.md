### 目录职责

| 目录 | 职责 | 说明 |
|------|------|------|
| 根目录 | 系统文件（SCHEMA/log/INDEX/SOP） | 不放知识内容 |
| {领域}/ | 该领域的所有知识页面 + source + 图片 | 按主题就近存放 |
| queries/ | 对话中产生的综合分析 | 知识复利的载体 |

### 图片存放规范

**所有图片一律存放在对应领域目录下，与 source/wiki 同目录。**

| 场景 | 存放路径 | 示例 |
|------|----------|------|
| 少量图片（<5 张） | 与 source/wiki 同目录 | `{领域}/` |
| 多张图片（≥5 张） | `{主题}-images/` 子目录 | `{领域}/gateway-images/` |

**命名规则**：`{序号}-{功能描述}.png`（有意义，不随机）

**禁止**：图片不得放在远离对应文档的位置。

- 使用 **kebab-case**（小写 + 短横线分隔）

### 领域目录
- 使用 kebab-case 命名
- 示例：`product-knowledge/`、`investment-notes/`、`learning/`

## 三、Source 文件规范

### 定义
Source 文件是从原始材料（飞书文档、网页文章、PDF、会议记录等）导出的**未经编译的完整原文**。

### 规则

| 规则 | 说明 |
|------|------|
| **不可变** | Source 文件一旦创建，永不修改 |
| **命名** | 必须以 `-source.md` 结尾 |
| **存放** | 放在对应领域的子目录中 |
| **一一对应** | 每个 `-source.md` 应有对应的编译后 `.md` 页面 |
| **完整性** | 必须包含完整原文，禁止只存摘要或大纲 |
| **最小体积** | 按来源类型分级报警（微信/飞书 < 3KB、网页 < 1.5KB、PDF < 2KB、粘贴 < 500B），详见 SKILL.md 第九节阈值表 |

### Source 文件头部模板

```markdown
---
source_type: feishu | wechat | web | local | pdf | direct
source_url: 原始链接（如有）
fetched_at: YYYY-MM-DD HH:MM
fetched_by: agent-name
---

# 文档标题

（完整正文内容）
```

## 三-b、Wiki 编译质量标准

Source 是原始文档的快照，Wiki 是从中提炼的结构化知识。编译质量直接决定知识库的价值。

### 编译质量参考

| 指标 | 标准 | 说明 |
|------|------|------|
| 信息保留率 | source 中 80% 以上的关键事实应出现在 Wiki 中 | 不能只提炼自己认为重要的，丢失用户可能需要的信息 |
| 压缩比 | Wiki 正文通常是 source 的 30-60% | 去掉评审记录、版本历史、会议签到表等噪音后的体量 |
| 结构要求 | 至少包含：一句话概述 + 2 个以上章节 | 纯文本块没有结构化价值 |
| 可读性 | 不看 source 也能理解 Wiki 内容 | Wiki 应自包含，不依赖 reader 已经读过 source |

### 常见噪音类型（编译时应去除）
- 评审记录、会议纪要、版本变更历史
- 会议签到表、审批流程信息
- 重复说明（同一事实在不同章节说了三遍）
- 飞书特有标签（如 @某人、评论批注）
- 与核心内容无关的行政信息

### 好 vs 坏的编译对比

**❌ 坏的编译**：
```
# 网关计费方案
本文介绍了网关计费方案的设计和实现。
## 背景
网关计费方案的背景。
## 方案
网关计费方案的方案。
```
问题：只提炼了章节标题，没有实际内容，跟没编译一样。

**✅ 好的编译**：
```
# 网关计费方案
> 网关设备采集电表数据后，通过 T-Building 平台的计费引擎实现分户计费。

## 数据采集流程
网关通过 RS485 接口采集电表读数，每 15 分钟上报一次...

## 计费引擎计算逻辑
T-Building 接收到电表数据后，按以下公式计算...

## 支持的分户模式
- 按面积分摊
- 按实际用量分摊
- 混合模式...

## 🔗 关联页面
- [T-Building 分户计费](../t-building/billing.md) — 计费数据下游消费方
- [楼宇网关](../hardware/gateway.md) — 数据采集上游设备
```
优点：保留了关键事实，结构清晰，有交叉引用。

## 三-c、跨领域文档处理规则

当一篇文档同时涉及多个领域时（如"网关计费方案"既属于 hardware 又属于 t-building）：

```
处理规则：
1. 选择"主要归属领域"存放 Wiki + source（按内容主体判断）
2. 在另一个领域中创建简短的引用页面：
   - 文件命名：同主页面
   - 内容：一句话摘要 + 链接指向主页面
   - 格式："> 本文完整内容见 [{领域A}/{name}](../{主要领域}/{name}.md)"
3. 两个页面都加交叉引用
4. INDEX.md 两个领域都列条目（引用页面标注"→ 详见 [主页面]"）
```

## 四、Wiki 页面结构规范

### 标准页面模板

```markdown
---
title: 页面标题
type: knowledge | reference | analysis
category: 所属领域
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - xxx-source.md
tags:
  - 标签1
  - 标签2
related:
  - "../other-dir/page.md"
---

# 页面标题

> 一句话概述（用于索引摘要）

## 正文内容...

---

## 🔗 关联页面
- [页面名称](../path/to/page.md) — 关联说明
```

### frontmatter 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 页面标题 |
| `type` | string | ✅ | `knowledge`（领域知识）/ `reference`（参考资料）/ `analysis`（分析产出） |
| `category` | string | ✅ | 所属领域 |
| `created` | date | ✅ | 创建日期 |
| `updated` | date | ✅ | 最后更新日期 |
| `sources` | array | ✅ | 源文件名列表 |
| `tags` | array | 推荐 | 关键词标签 |
| `related` | array | 推荐 | 关联页面相对路径 |

## 五、交叉引用规范

### 语法
使用**标准 Markdown 链接**格式，不使用 `[[双链]]` 语法：

```markdown
[页面显示名称](../relative/path/to/page.md) — 一句话说明
```

### 路径规则

| 关系 | 格式 | 示例 |
|------|------|------|
| 同目录 | `page.md` | `[网关](gateway.md)` |
| 上级目录 | `../page.md` | `[平台](../platform-overview.md)` |
| 兄弟目录 | `../other/page.md` | `[计费](../t-building/billing.md)` |

### 关联页面区块
放在页面最末尾，用 `---` 分割线分隔：

```markdown
---

## 🔗 关联页面
- [页面名](../path/page.md) — 说明
```

## 六、工作流规范

### 6.1 Ingest（新文档入库）
详见 `INGEST-SOP.md`。核心九步：去重 → 抓取 → 保存 Source → 编译 Wiki → 图片本地化 → 更新索引 → 完整性自检 → Query 沉淀 → Git 提交。

### 6.2 Query 沉淀（对话知识存回）
有价值的综合回答 → 整理为 Markdown → 保存到 queries/ 或对应领域 → 更新索引和日志。

**触发时机**：
- 回答涉及多个 Wiki 页面的信息串联
- 用户说"存一下"
- Agent 主动判断值得保留

### 6.3 Lint 巡检（定期健康检查）
建议每 1-2 周或大规模更新后执行。详见 `references/LINT-checklist.md`（Skill 安装后存放在 Skill 目录内）。

## 七、Git 提交规范

### Commit Message 格式
```
[类型] 简述内容
```

### 类型说明

| 类型 | 用途 | 示例 |
|------|------|------|
| `[ingest]` | 新文档入库 | `[ingest] 新增网关单品知识页面` |
| `[query]` | Query 沉淀 | `[query] 沉淀多平台联动分析` |
| `[lint]` | 巡检修复 | `[lint] 修复 3 处失效链接` |
| `[schema]` | 规范变更 | `[schema] 更新目录结构` |
| `[index]` | 索引更新 | `[index] 同步新增 5 个条目` |
| `[batch]` | 批量操作 | `[batch] 批量入库 12 篇文章` |

### 原则
- 每个操作独立 commit
- Commit message 不包含敏感信息
- 使用通用描述
