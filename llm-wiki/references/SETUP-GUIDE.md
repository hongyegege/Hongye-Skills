# 安装指南 — LLM Wiki Setup Guide

> 本文件指导 Agent 在首次安装 llm-wiki skill 后，如何为用户初始化一个全新的知识库。
> 预计耗时：5-10 分钟。

---

## 一、信息收集（向用户确认）

在开始 Setup 前，向用户确认以下 6 项配置：

```
┌──────────────────────────────────────────────────────────────┐
│  LLM Wiki 知识库初始化配置                                      │
├──────────────────────────────────────────────────────────────┤
│  1. 知识库名称：_______________（如：产品知识库、投资笔记）       │
│  2. 知识库根目录：_______________（默认：workspace/wiki/）      │
│  3. 初始领域分类：_______________（至少 1 个，逗号分隔）         │
│     示例：产品, 技术, 投资, 学习, 管理                          │
│  4. 是否启用 Git 版本管理：是 / 否（推荐：是）                  │
│  5. Git 远程仓库地址：_______________（可选，用于云端备份）      │
│  6. 主要文档来源：_______________（可多选）                     │
│     □ 飞书文档  □ 微信公众号  □ 网页/博客  □ PDF  □ 本地文件    │
└──────────────────────────────────────────────────────────────┘
```

**快捷方式**：如果用户说"用默认配置"，则：
- 知识库名称 = "个人知识库"
- 根目录 = `workspace/wiki/`
- 初始领域 = `general/`（单一通用领域，后续可拆分）
- Git = 是（本地 git init，不设远程）
- 文档来源 = 全部启用

## 二、执行初始化

### Step 1：创建目录骨架

```bash
# 创建根目录
mkdir -p {知识库根目录}

# 创建各领域子目录
for domain in {领域1} {领域2} ...; do
  mkdir -p "{知识库根目录}/$domain"
done

# 创建 queries 目录
mkdir -p {知识库根目录}/queries
```

### Step 2：生成定制化 SCHEMA.md

```
读取：references/SCHEMA-template.md
替换以下变量：
  {知识库名称} → 用户提供的名称
  {创建日期} → 当天日期（YYYY-MM-DD）
  {维护者} → 用户名 + Agent 名
  {知识库根目录} → 用户指定的路径

  领域目录展开规则：
    SCHEMA-template.md 中有 {领域A}、{领域B} 占位符。
    用户配置了 N 个领域，就展开 N 个目录条目，每个条目格式相同。
    例：用户配置「产品,技术,投资」→ 展开为 3 个目录块（product/、tech/、investment/）。

输出：{知识库根目录}/SCHEMA.md
```

### Step 3：复制 INGEST-SOP

```
读取：references/INGEST-SOP-template.md
复制为：{知识库根目录}/INGEST-SOP.md
（无需替换变量，SOP 模板已是通用格式）
```

### Step 4：初始化 INDEX.md

```markdown
# {知识库名称} — 全仓库索引

> 唯一索引入口，每次 Ingest/Query 后自动更新。
> 创建时间：{YYYY-MM-DD}

---

## 📊 统计摘要

| 指标 | 数值 |
|------|------|
| Wiki 页面总数 | 0 |
| Source 文件数 | 0 |
| 图片资产数 | 0 |
| 领域数 | {N} |
| Query 沉淀数 | 0 |

---

{对每个领域生成一个空表格}

## 📦 {领域名称}

| 页面 | 类型 | 摘要 | Source | 图片 | 更新日期 |
|------|------|------|--------|------|----------|
| （暂无条目） | | | | | |

---

## 🧠 Query 沉淀

| 页面 | 主题 | 源文档 | 更新日期 |
|------|------|--------|----------|
| （暂无条目） | | | |

---

*本索引由 Agent 自动维护，每次 Ingest/Query 后更新。*
```

### Step 5：初始化 log.md

```markdown
# {知识库名称} — 操作日志

> 记录每次 Ingest / Query / Lint / 架构变更操作。

---

## [{YYYY-MM-DD}] Setup | 知识库初始化
- 产出: SCHEMA.md, INDEX.md, INGEST-SOP.md, log.md
- 领域: {领域列表}
- Git: {是/否}
- 说明: 由 llm-wiki skill v1.0.0 初始化
```

### Step 6：Git 初始化（如启用）

```bash
cd {知识库根目录}
git init
git add -A
git commit -m "[setup] 知识库初始化：{知识库名称}"

# 如果提供了远程仓库
git remote add origin {远程地址}
git push -u origin main
```

## 三、验证清单

Setup 完成后，逐项确认：

- [ ] **目录骨架**：根目录 + 各领域子目录 + queries/ 已创建？
- [ ] **SCHEMA.md**：变量已全部替换（无 `{{xxx}}` 残留）？
- [ ] **INGEST-SOP.md**：已复制到知识库根目录？
- [ ] **INDEX.md**：已创建，包含各领域空表格？
- [ ] **log.md**：已创建，包含首条 Setup 记录？
- [ ] **Git**（如启用）：首次 commit 成功？远程 push 成功（如有）？

**验证命令**：
```bash
# 检查目录结构
find {知识库根目录} -type f | sort

# 检查变量替换残留
grep -rP '\{[A-Z\u4e00-\u9fff]' {知识库根目录}/SCHEMA.md

# 检查 Git 状态
cd {知识库根目录} && git log --oneline
```

## 五、后续扩展

### 新增领域
用户说"新增一个 XXX 领域"时：
1. `mkdir -p {知识库根目录}/{新领域}`
2. 更新 SCHEMA.md 中的领域列表
3. 更新 INDEX.md 新增对应表格区块
4. 追加 log.md 记录
5. Git commit

### 迁移已有知识库
如果用户已有一批 Markdown 文件想迁入：
1. 将文件复制到对应领域目录
2. 为每个文件检查是否需要创建 `-source.md`
3. 补充 frontmatter（如缺失）
4. 更新 INDEX.md
5. 执行一次 Lint 巡检
6. Git commit

### 导出知识库
如需导出整个知识库：
1. 整个目录打包（zip/tar）
2. 或 `git clone` 远程仓库
3. INDEX.md 可作为阅读入口
