# Question Gate

生成 HTML 前必须完成信息门槛。每轮只问当前最影响页面结构的 1–3 个问题，并在问题前显示缺口类别和当前已确认内容。

## Required categories

| 类别 | 必须确认的内容 |
|---|---|
| 目标 | 产品/功能要解决什么问题，Demo 给谁看 |
| 主路径 | 用户从哪里开始，经过哪些页面/动作，最终看到什么结果 |
| 页面 | 页面清单、页面入口、返回关系、页面是否可被能力开关隐藏 |
| 控件 | 按钮、输入框、列表项、滑动、弹窗和可点击区域 |
| 状态 | 正常、加载、成功、失败、空、过期、确认/取消中适用的状态 |
| 内容 | 标题、按钮、错误文案、示例数据、语言和格式 |
| 视觉 | 主题色、字体、设备框、品牌资产和必须保留/禁止元素 |
| Mock | 是否离线、异步延迟、随机性、结果反馈和重置规则 |
| 验收 | 必须能现场演示的 2–5 条路径 |

## Blocking rules

- 缺少主路径、页面入口或关键状态：阻塞；
- 缺少会改变布局的字段/控件：阻塞；
- 缺少真实品牌资产但产品需要呈现可识别品牌：阻塞并索要资产或明确允许中性占位；
- 视觉细节不影响结构时，可以在 manifest 标为 `pending`，但不能隐藏该待确认项；
- 用户明确要求“先给假设版”时，才允许生成；假设必须逐条写入 `meta.assumptions` 和交付报告；
- 用户未回答时，不得自行继续生成。

## Conversation record

每次追问后保留：

```text
已确认：...
本轮缺口：...
待确认：...
本轮问题：...
```

只有所有 blocking rules 通过，才输出“信息门槛通过”并开始模板生成。
