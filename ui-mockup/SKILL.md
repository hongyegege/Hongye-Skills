# UI Mockup — PRD 到界面效果图工作流

## 技能简介

本 Skill 是一个**从 PRD 到界面效果图的结构化编排引擎**，覆盖 5 个步骤：

1. **确认现有交互逻辑** — 结构化理解当前页面
2. **明确新增/改动点** — 增量思维，只改需要改的
3. **生成 UI Prompt** — 基于 RASCEF + Atomic Prompting 框架生成高质量 Prompt
4. **AI 出图** — 截图 + Prompt 喂给绘图工具
5. **评审与迭代** — 不满意时的修正路径

**开箱即用**：所有核心能力已内置，无需额外安装。

---

## 核心原则

### ❌ 禁止
- 另起炉灶（新功能必须嵌入现有流程）
- 改动未描述的区域
- 一次出图就期望完美（预期 2-3 轮迭代）
- 跳过 Step 1 的确认环节

### ✅ 必须
- 先确认现有逻辑，再讨论改动
- Prompt 中包含角色设定（Role）和硬性约束（MUST FOLLOW）
- 明确标注"哪些区域不动"和"哪些区域改动"
- 提供 ASCII 线框图示意改动位置和完整页面

## 执行流程（5 步）

```
Step 1: 确认 & 分析现有交互逻辑
    ↓
Step 2: 明确本次新增/改动点
    ↓
Step 3: 生成 UI 效果图 Prompt
    ↓
Step 4: 截图 + Prompt → AI 绘图工具 → 出图
    ↓
Step 5: 评审与迭代
```

---

### Step 1: 确认 & 分析现有交互逻辑

**执行者**：操作者 + AI 助手

**怎么做**：
- 把现有产品页面的交互流程以文本或图片形式提供给 AI
- 给 AI 提供/接入产品知识库，让 AI 理解现有功能能力与逻辑
- 包含：页面功能目标、交互步骤、字段清单、交互规则
- 若 AI 无多模态能力，提示操作者以文本方式提供

**确认方式**（必须满足全部条件才能进入 Step 2）：

AI 需以结构化方式复述以下内容，操作者逐项确认 ✅/❌：
1. 页面包含哪些功能区域？
2. 每个区域有哪些核心字段和控件？
3. 页面间的跳转关系是什么？
4. 当前设计中有哪些已知痛点或待优化点？

**输出**：AI 理解并复述现有逻辑，操作者逐项确认后双方达成一致

**质量检查**：
- [ ] AI 的复述是否覆盖了所有功能区域？
- [ ] 字段和控件描述是否与截图/文档一致？
- [ ] 操作者是否已逐项确认（4 项全部 ✅）？

---

### Step 2: 明确本次新增/改动点

**执行者**：操作者 + AI 助手讨论

**怎么做**：
- 操作者说明核心目标和边界，或提供 PRD / 低保真原型 / 高保真 UI 设计图
- AI 基于现有逻辑，提出功能叠加方案
- 反复对齐，直到方案双方认可

**关键原则**：
- 新功能嵌入现有流程，不另起炉灶
- 只改需要改的，不动已有的
- 改动点按优先级排序（P0 必改 > P1 建议改 > P2 可选改）

**输出**：确认的新增功能清单 + 交互变更点（含优先级标注）

**质量检查**：
- [ ] 新增功能清单是否完整？
- [ ] 每个改动点是否标注了优先级？
- [ ] 改动范围是否合理？

---

### Step 3: 生成 UI 效果图 Prompt

**执行者**：AI 助手

读取 `references/prompt-template.md` 获取完整的 Prompt 模板（RASCEF + Atomic Prompting 结构），然后基于 Step 1-2 的信息填充模板。

**Prompt 核心结构**（7 节）：
1. **角色设定**（RASCEF-Role）— 定义 AI 为资深 UI/UX 设计师
2. **页面定位**（Atomic-Organism 层）— 整体场景和视觉方向
3. **现有页面结构**（Atomic-Molecule 层）— 区域划分，标注不变/改动
4. **新增 UI 改动**（Atomic-Atomic 层）— 精细细节：位置、结构、交互
5. **卡片视觉规范**（Atomic-Parameters 层）— 圆角、阴影、配色、字号
6. **最终页面效果预期** — 完整 ASCII 线框图
7. **硬性约束 + AI 工具参数** — MUST FOLLOW + 目标工具参数

**质量检查**：
- [ ] 是否包含角色设定？
- [ ] 是否明确标注了"哪些区域不动"？
- [ ] 是否明确标注了"哪些区域改动"？
- [ ] 改动区域是否有 ASCII 线框图示意？
- [ ] 完整页面是否有 ASCII 线框图？
- [ ] 硬性约束是否至少 4 条？
- [ ] 视觉规范是否描述清楚？
- [ ] 交互状态是否说明（默认、展开、加载、空数据）？
- [ ] 是否填写了 AI 绘图工具参数？

---

### Step 4: 截图 + Prompt → AI 绘图工具 → 出图

**执行者**：操作者

**怎么做**：
1. 将现有页面截图 + Step 3 的 Prompt 一起喂给 AI 绘图工具
2. Prompt 中已明确哪些区域不动、哪些区域改动
3. AI 基于截图理解现有布局，按 Prompt 描述进行 UI 叠加

**注意事项**：
- 截图质量要高（≥ 1920x1080），避免模糊或遮挡
- 若 AI 绘图工具不支持图片输入，需在 Prompt 中更详细描述现有结构
- 若 AI 助手不支持多模态，可跳过此步，只完成 Step 3

**输出**：包含新功能后的界面效果图（初版）

**质量检查**：
- [ ] 截图质量是否达标？
- [ ] 是否正确选择了 AI 绘图工具？

---

### Step 5: 评审与迭代

**执行者**：操作者 + AI 助手

**评审清单**（逐项检查）：
- [ ] 新元素是否与原页面风格一致？
- [ ] 未改动区域是否完全保持原样？
- [ ] 交互状态是否正确表达？
- [ ] ASCII 线框图与实际出图是否吻合？
- [ ] 新增元素的层级关系是否正确？

**不满意时的修正路径**：

| 问题类型 | 具体表现 | 修正策略 | 回到哪一步 |
|---------|---------|---------|-----------|
| 风格漂移 | 新卡片颜色、圆角不一致 | 加强视觉约束词，增加具体色值 | Step 3 第四节 |
| 改动范围过大 | AI 自由发挥了未描述的元素 | 增加 ⛔ 约束 + negative prompt | Step 3 第六节 |
| 细节模糊 | 控件样式、图标不清晰 | 补充 Atomic 层级精细描述 | Step 3 第三节 |
| 布局错乱 | 位置不对、遮挡关系错误 | 调整 ASCII 线框图，增加参照物 | Step 3 第五节 |
| 工具不适配 | 当前工具无法满足需求 | 切换到更适合的工具 | Step 4 换工具 |
| 需求理解偏差 | 新增功能与 PRD 不符 | 重新对齐需求边界 | Step 2 |

**迭代上限**：同一工具迭代不超过 3 轮。3 轮后仍不满意，切换工具或重新审视 Prompt 结构。

---

## 常见陷阱与应对

| 陷阱 | 表现 | 应对策略 |
|------|------|---------|
| 描述过载 | Prompt 太多细节，AI 无法聚焦 | 优先描述改动区域，不变区域用"与截图一致"概括 |
| 风格漂移 | 新卡片风格和原页面不一致 | 第四节给出具体色值、圆角、字号等硬参数 |
| 截图质量差 | 截图分辨率不够或有遮挡 | 截图前确保页面完整，分辨率 ≥ 1920x1080 |
| 过度改动 | AI 自由发挥了未描述的元素 | 第六节增加 ⛔ 约束 + negative prompt |
| 确认不充分 | Step 1 草草过场 | 严格执行 4 项确认清单 |
| 缺少迭代 | 一次出图就期望完美 | 预期 2-3 轮，按修正路径表调优 |
