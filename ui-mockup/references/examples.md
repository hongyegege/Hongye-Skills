## 示例 1：简单场景 — 智能家居控制面板新增"能耗分析"卡片

### Step 1 复述

> AI 复述：当前智能家居控制面板包含 3 个区域——
> ① 顶部状态栏（显示在线设备数、场景模式）
> ② 设备卡片区（灯光、空调、窗帘，每个卡片含开关 + 状态）
> ③ 底部快捷操作区（一键回家/离家模式）
> 配色为深色主题，圆角 12px，卡片间距 16px。
>
> 操作者确认：✅ 全部正确

### Step 2 改动清单

- P0：在设备卡片区下方新增"能耗分析"卡片
- P1：卡片包含今日/本周/本月用电量 + 趋势图
- P2：点击卡片可跳转详细能耗页面

### Step 3 生成的 Prompt

```markdown
# 智能家居控制面板 — 新增"能耗分析"卡片 UI 效果图 Prompt

## 角色设定
你是一位拥有 10 年经验的资深 UI/UX 设计师，擅长在现有界面风格基础上进行增量式设计。

## 一、页面定位
智能家居 APP → 首页控制面板
用户通过此页面查看和控制家中所有智能设备。
整体视觉风格：深色主题（#1A1A2E 背景），科技蓝点缀（#4CC9F0），圆角 12px。

## 二、现有页面结构
### 区域 A：顶部状态栏（不变）
- 在线设备数：数字 + "台在线"
- 当前场景模式：文字标签

### 区域 B：设备卡片区（不变）
- 每个设备卡片：图标 + 名称 + 开关控件 + 状态文字
- 卡片布局：2 列网格

### 区域 C：底部快捷操作区（不变）
- 一键回家 / 一键离家 按钮

### 区域 D：新增区域 ⚠️（位于区域 B 和区域 C 之间）

## 三、本次新增 UI 改动

### 改动 1：新增「能耗分析」卡片
- **位置**：在设备卡片区（区域 B）下方，快捷操作区（区域 C）上方
- **卡片标题**：⚡ 能耗分析
- **卡片结构**：
  ```
  ┌─────────────────────────────────┐
  │ ⚡ 能耗分析              [详情>] │
  ├─────────────────────────────────┤
  │  今日         本周       本月   │
  │  12.5 kWh   87.3 kWh  342 kWh │
  │  ─────────────────────────────  │
  │  📈 [趋势折线图: 近7天用电量]    │
  │       较上周 ↓12%              │
  └─────────────────────────────────┘
  ```
- **交互细节**：
  - 默认状态：展示"今日"数据，趋势图显示近 7 天
  - Tab 切换：今日/本周/本月，切换时数据区和趋势图同步更新
  - 点击"详情>"：跳转到能耗分析详情页
  - 加载状态：骨架屏占位
  - 空数据状态：显示"暂无能耗数据"

## 四、卡片视觉规范
- **圆角**：12px（与现有卡片一致）
- **阴影**：0 4px 12px rgba(0,0,0,0.3)（深色主题阴影）
- **配色**：
  - 卡片背景：#16213E
  - 标题文字：#E8E8E8
  - 数据文字：#4CC9F0（科技蓝，与主题一致）
  - 趋势下降：#52C41A（绿色）
  - 趋势上升：#FF4D4F（红色）
- **字号**：标题 16px / 数据 24px（加粗）/ 辅助 12px
- **间距**：卡片内边距 20px，与上方设备卡片区间距 16px

## 五、最终页面效果预期
```
┌──────────────────────────────────────┐
│ 🏠 智能家居    5台在线  |  回家模式   │  ← 区域A（不变）
├──────────────────────────────────────┤
│ ┌──────────┐  ┌──────────┐          │
│ │💡 客厅灯  │  │❄️ 空调    │          │  ← 区域B（不变）

## 六、硬性约束（MUST FOLLOW）
1. ⛔ 区域 A、B、C 必须与截图完全一致，禁止任何修改
2. ✅ 仅在区域 D 叠加新的"能耗分析"卡片
3. 🎨 新卡片必须使用深色主题配色（#16213E 背景），圆角 12px
4. 📐 新卡片宽度 = 设备卡片宽度，高度自适应
5. 🚫 不要添加任何未描述的装饰元素
6. 🖼️ 输出：高保真 UI 效果图，分辨率 1080x2400（手机竖屏）

## 七、AI 绘图工具参数
### 目标工具：DALL-E 3
- **画面比例**：9:16（手机竖屏）
- **画质关键词**：high fidelity mobile UI mockup, dark theme, pixel-perfect, professional smart home app
- **排除关键词**：light theme, cartoon, 3D render, blurry, watermark

## 示例 2：复杂场景 — 商用空调管理平台新增"故障预警"模块

> 此示例展示涉及多个区域联动改动的复杂场景。因篇幅原因，仅展示与简单场景的关键差异点。

### 关键差异对比

| 维度 | 简单场景（示例1） | 复杂场景（示例2） |
|------|-----------------|-----------------|
| 改动区域数 | 1 个新增区域 | 3 个区域联动改动 |
| 交互复杂度 | Tab 切换 + 跳转 | 多状态联动（告警/确认/处理/关闭） |
| 数据关联 | 独立数据 | 与现有设备列表数据关联 |
| Prompt 长度 | 约 50 行 | 约 150-200 行 |
| 迭代轮次 | 通常 1-2 轮 | 通常 2-3 轮 |

### 复杂场景的额外注意事项

1. **多区域联动描述**：在第三节中需要描述多个区域之间的数据联动关系
   - 例如：设备列表中的设备状态变化 → 触发告警卡片更新 → 告警详情面板联动

2. **更详细的硬性约束**：第六节需要为每个不变区域单独列出约束
   ```
   1. ⛔ 顶部导航栏必须与截图完全一致
   2. ⛔ 左侧菜单栏必须与截图完全一致
   3. ⛔ 设备列表区域的现有列必须保持不变
   4. ✅ 仅在设备列表区域新增"告警状态"列
   5. ✅ 仅在右侧新增"告警详情"面板
   ...
   ```

3. **完整线框图用不同标记区分**：
   ```
   ┌──────────────────────────────────────┐
   │ [顶部导航] （不变）                    │
   ├───────┬──────────────────────────────┤
   │       │ ╔════════════════════════╗   │
   │ [左侧 │ ║ ⚠️ 设备列表（新增列）   ║   │
   │  菜单]│ ║  ...                    ║   │
   │ (不变)│ ╚════════════════════════╝   │
   │       ├──────────────────────────────┤
   │       │ ╔════════════════════════╗   │
   │       │ ║ ⚠️ 告警详情面板（新增） ║   │
   │       │ ╚════════════════════════╝   │
   └───────┴──────────────────────────────┘
   ```

4. **状态机描述**：复杂交互需要补充状态转换表
   ```
   | 当前状态 | 触发事件 | 目标状态 | UI 变化 |
   |---------|---------|---------|--------|
   | 正常 | 检测到异常 | 告警中 | 列表行变红 + 面板弹出 |
   | 告警中 | 点击确认 | 已确认 | 状态标签变为"已确认" |
   | 已确认 | 处理完成 | 已处理 | 状态标签变为"已处理" |
   | 已处理 | 24h无复发 | 正常 | 恢复默认样式 |
   ```

## 示例 3：实战验证 — T-Building 商户平台「新建日程」新增锁定/解锁功能

> 此示例已在 GPT-image-2 上实战验证，出图效果非常满足要求。
> 展示了 4 个改动联动 + 条件展示型 UI 的复杂场景。

### 与示例 1/2 的关键差异

| 维度 | 示例 1（简单） | 示例 2（复杂） | 示例 3（实战） |
|------|-----------------|-----------------|----------------|
| 改动数 | 1 个新增 | 3 个联动 | 4 个联动 |
| 条件展示 | 无 | 未涉及 | 改动 4（设备不支持提示） |
| 辅助文案 | 无 | 未涉及 | 时间范围锁的灰色说明文字 |
| 角色设定 | 有 | 有 | 无（直接投喂 GPT-image-2） |
| AI 工具参数 | 有 | 有 | 无（直接投喂） |
| 出图工具 | DALL-E 3 | - | GPT-image-2 |
| 实战效果 | 未验证 | 未验证 | ✅ 验证通过 |

### 核心学习点

1. **使用说明优先**：开头用 `> 使用说明：请参考附件图片，配合以下内容生成` 直接告诉 AI 截图和 Prompt 的关系
2. **ASCII 图中直接标注状态**：`[ON]`/`[OFF]`、`← 默认关闭（灰色）`、`← 未勾选时灰色置灰`，比文字描述更直观
3. **条件展示型改动**：改动 4（设备不支持锁定提示）明确写了展示条件 + 隐藏条件 + 展示位置
4. **辅助说明文案**：时间范围锁标题下的灰色小字"在日程周期内保持锁定，结束后自动解锁"帮助 AI 理解功能语义
5. **省略角色设定和工具参数**：直接投喂专用图像工具时，这两节可以省略，不影响效果

## 示例使用建议

1. **先读示例 1**：理解模板的基本填写方式和粒度
2. **再读示例 2 的差异对比**：理解复杂场景需要额外补充什么
3. **不要照抄**：根据你的实际产品和页面结构调整内容
4. **关键学习点**：
   - ASCII 线框图是最重要的视觉沟通工具
   - 具体色值 > 模糊描述（"#1677FF" 比 "蓝色" 好）
   - 交互状态覆盖越全，出图越准确
   - 硬性约束越多，AI 自由发挥空间越小，结果越可控
