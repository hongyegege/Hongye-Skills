> 基于 RASCEF（Role-Action-Steps-Context-Examples-Format）+ Atomic Prompting（Organism-Molecule-Atomic-Parameters）双层框架设计。

## 各节填写指南

### 使用说明（Prompt 头部）
- 明确告知 AI 配合截图使用
- 一句话说明截图与 Prompt 的关系
- 实战验证：有使用说明 > 无使用说明，AI 对截图的参照准确度更高

### 角色设定（RASCEF-Role）
- 定义为"资深 UI/UX 设计师"
- 强调"增量式设计"和"保持未改动区域一致"
- **专用图像生成工具（GPT-image-2、DALL-E 3 等）：可省略**，直接投喂效果更好
- **通用 LLM（ChatGPT、Claude 等）：建议保留**，帮助 AI 进入正确的设计思维

### 页面定位（Atomic-Organism）
- 写清楚产品路径（面包屑）
- 一句话说清页面做什么
- 描述整体视觉风格（配色体系、设计系统、主题）

### 现有页面结构（Atomic-Molecule）
- 按区域（Region）划分，每个区域一个子标题
- 列出核心字段和控件类型
- **重点标注改动区域**，用 ⚠️ 标记
- 不变区域可以简要描述，改动区域要详细

### 新增 UI 改动（Atomic-Atomic）
- 每个改动独立一个子标题
- **必须有 ASCII 线框图**——这是最有效的视觉传达方式
- **在 ASCII 图中标注默认状态**：用 [ON]/[OFF]、[展开]/[折叠] 直接标注在控件旁
- **辅助说明文案**：如果功能有"一句话解释"，在标题下方用灰色小字展示
- **未激活状态用注释标注**：如 `← 未勾选时灰色置灰`
- 交互细节要覆盖 5 种状态：默认、展开/收起、校验、加载、空数据
- 位置描述用参照物（"在 XX 下方"），不用绝对坐标
- **条件展示型 UI**：当某个元素仅在特定条件下展示时（如警告提示、兼容性提示），使用「改动 N：条件展示型 UI」模式，明确写出展示条件、隐藏条件、展示位置

### 卡片视觉规范（Atomic-Parameters）
- 给出**具体数值**，不要只写"与现有一致"
- 配色用 hex 色值
- 字号用 px
- 阴影用 CSS 语法
- 这些参数是防止风格漂移的硬约束

### 最终页面效果预期
- 完整的 ASCII 线框图，覆盖整个页面
- 用双线边框 `╔══╗` 标注改动区域
- 用 `（不变）` 标注不变区域
- 这是 AI 理解整体布局的关键输入

### 硬性约束
- 至少 4 条，推荐 5-6 条
- 用 ⛔✅🎨📐🚫🖼️ emoji 前缀增强可读性
- 第一条必须是"不变区域禁止修改"
- 最后一条指定输出格式和分辨率

### AI 绘图工具参数（可选）
- **直接投喂 GPT-image-2 / DALL-E 3 时可省略**
- 通过通用 LLM 中转时建议填写
- Midjourney：写 `--ar`、`--style`、`--v` 参数
- DALL-E 3：写自然语言风格描述
- Stable Diffusion：写 positive/negative prompt + 权重
- 通用关键词：`high fidelity UI mockup, pixel-perfect, professional`
- 通用排除：`blurry, low quality, cartoon, 3D render, watermark`

## 实战经验总结（来自 GPT-image-2 验证）

以下优化来自实际使用 GPT-image-2 生成效果图的复盘，已证实可显著提升出图质量：

1. **使用说明 > 角色设定**：对专用图像工具，开头的"请参考附件截图，配合以下内容生成"比角色设定更有效
2. **ASCII 图中标注状态**：在控件旁直接写 [ON]/[OFF]，比在交互细节里文字描述更直观
3. **条件展示要显式声明**：如"若全部支持则不展示"——没有这句话，AI 可能会无条件展示
4. **多改动联动时，完整线框图最重要**：第五节的完整 ASCII 图是 AI 理解多卡片并列关系的关键输入
5. **卡片说明文案增强功能理解**：一行灰色小字说明（如"在日程周期内保持锁定，结束后自动解锁"）能帮助 AI 更准确理解功能语义
