# 小T管家AI智能体发布会页设计说明

## Visual Design

页面目标是面向空调研发总经理、管理层和普通职工的产品发布会演示页，整体表达从“技术评审说明”转为“产品能力发布”。首屏强调“暖通项目管理的未来范式”，把小T管家定位为从数据看板走向 AI 智能管理的项目运营入口。页面采用深色沉浸式舞台、IOC 控制台网格、运行态可视化墙和分层架构舱，让观众第一眼感知这是面向真实项目运营的 AI 智能体产品。

默认主色为近黑背景、石墨卡片、蓝色 AI 识别、绿色执行与节能、琥珀色风险/数据、珊瑚色治理提示、紫色接入层。页面支持一键切换浅色 UI 与暗黑 UI：暗黑 UI 是默认发布会舞台风格，浅色 UI 通过 `body[data-theme="light"]` 覆盖全局色彩变量、背景、卡片、顶部栏、控制台和架构舱，使同一套内容适合明亮会议室或投影场景。所有主要卡片和按钮保持 8px 圆角。首屏 Hero 使用最大宽度约束的双列网格，左侧发布文案与右侧运行态可视化作为同一内容组居中，避免大屏展示时中间空洞。工作原理第一层“用户输入”及其输入示例统一使用蓝色。技术架构板块使用深色/浅色均可适配的分层架构舱，五层主架构与右侧治理能力并列呈现，层级色彩、网格背景和数据层圆柱节点增加视觉层次。

## Page Sections

1. Hero / 发布主题：保留为首屏内容，但不出现在顶部导航。主标题为“让平台从数据看板，走向 AI 智能管理”，说明 6 大 AI 智能体包含设备集控、能耗分析、能效优化、运行报告、故障诊断、售后助手。首屏指标为“6 个智能体”“1 句话需求”“有据可查”。
2. Live Demo / 产品演示：主标题为“一句话触发对应的AI智能体，看它如何工作。”，说明点击右侧场景后，小T管家会理解需求、调用工具、生成方案，并在执行前请用户确认。右侧场景按钮包含运行时长分析、能效优化方案、设备集控、故障诊断、运行报告生成 5 个场景。
3. Multi-Platform / 多端入口：主标题为“随时随地，一句话搞定。”，分 Web 端和 App 端两张卡。Web 端强调侧边对话窗、页面上下文、报告导出和批量操作；App 端强调底部 Tab、移动场景快速响应和故障提醒即时推送。
4. Features / 核心能力：主标题为“6 大 AI 智能体，覆盖运营全场景”，6 张能力卡分别介绍设备集控、能耗分析、能效优化、运行报告、故障诊断、售后助手，并用 proof 文案说明业务亮点。
5. How It Works / 工作原理：主标题为“小T管家如何工作。”，副说明为“五步闭环:输入→理解→调度→取数→交付，步步留痕,清晰可溯”。5 层结构依次为“用户输入、意图理解、智能体调度、数据检索与调用、结果交付”。
6. Data Flow / 执行链路：主标题为“从数据到行动。”，三列解释“数据从哪来、小T管家处理、产出什么”，帮助非技术听众理解系统如何接入业务并形成可执行结果。
7. Multi-Project / 安全审计：主标题为“一套系统，服务所有项目。”，说明项目数据隔离、按角色分配权限、使用量可控。
8. Architecture / 技术架构：主标题为“IOC 平台 AI 智能体技术架构。”，放在最后。左侧用接入层、编排层、智能体层、能力层、数据层五层架构解释系统构成，右侧用管理后台、安全与监控两组能力说明治理闭环。

## Interaction Design

页面只有一个内联脚本，所有事件绑定都作用在 `#page-root` 范围内。Hero 发布主题保留为首屏内容，但不在顶部导航中显示；顶部导航锚点对应后续 7 个可跳转页面区块：产品演示、多端入口、核心能力、工作原理、执行链路、安全审计、技术架构。顶部栏右侧有主题切换按钮，默认显示“浅色UI”，点击后切换到浅色风格并改为“暗黑UI”；再次点击切回暗黑风格。当前选择通过 `localStorage` 的 `xiaot-launch-theme` 保存，无法写入本地存储时仍可在当前页面生效。`#s3` 是隐藏结构锚点，仅用于保持生成器校验兼容，不作为可见板块。

产品演示区使用 `scenes` 对象驱动内容切换。点击右侧任一 `data-scene` 按钮后，状态机会依次进入“待命、识别中、路由中、生成中、待确认/报告就绪”，并同步更新用户输入、AI 叙述、指标、行动计划、处理过程和步骤进度。

设备集控场景隐藏“调整节能目标”按钮，确认按钮显示“确认执行控制”，确认后显示“指令已下发”。故障诊断场景隐藏节能目标按钮，确认按钮显示“确认处置建议”，确认后显示“处置建议已保存”。运行报告场景确认按钮显示“导出报告”，确认后显示“报告文件已生成”。运行时长分析与能效优化场景保留“调整节能目标”，弹层滑块范围为 10% 到 26%，保存后同步更新按钮标签和能效指标。重置演示会回到运行时长分析并恢复 18% 节能目标。

## Change Notes

后续小改建议先改本 `page-design.md`，再让 Codex 对照 HTML 增量更新。修改产品名称时，需要同步 `<title>`、顶部品牌、Hero、产品演示和核心能力中的名称。修改首屏定位时，需要同步 Hero eyebrow、主标题、主说明、CTA、三个指标和右侧运行态可视化文案。修改顶部导航时，应同步导航锚点、Page Sections 顺序和 Copy Inventory；Hero 发布主题不在顶部导航中显示。

修改演示链路时，优先更新脚本里的 `scenes` 对象，同时同步右侧场景按钮、处理步骤、行动计划、确认按钮文案和本设计说明的 Copy Inventory。新增或删减页面区块时，仍需保留 Hero、Live Demo、Features 三类核心发布会区域，并保持发布叙事完整。新增面向非技术听众的内容时，优先使用“用户说一句话、小T理解、智能体调度、确认执行、结果可追溯”的表达框架。

修改视觉风格时，优先调整 CSS `:root` 中的 `--bg`、`--surface`、`--cyan`、`--green`、`--amber`、`--coral`、`--violet` 等默认暗黑变量，并同步检查 `body[data-theme="light"]` 下的浅色变量和组件覆盖规则。主题切换按钮依赖 `#themeToggle`、`#themeLabel`、`body[data-theme]` 和脚本里的 `applyTheme / saveTheme`，不要新增第二段脚本。修改技术架构时，应同步 `#architecture` 的分层节点、右侧治理栏、响应式网格和顶部导航锚点，并保持该板块位于页面最后。不要重新显示年份；footer 保持“© POWERED BY EAGLE LAB”。
