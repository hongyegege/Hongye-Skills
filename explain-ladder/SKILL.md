# Explain Ladder（四层讲解法）

## Purpose

背景：2026-10-02 Andrej Karpathy 在 X 发帖指出——当 AI 输出速度超过人类理解速度，瓶颈不在生成而在理解。他给出四层递进的讲解格式，一层比一层更易理解：

1. **ASD-STE100 技术语言**——受控英语写作，极度精准、无歧义
2. **图表可视化**——结构一眼看懂
3. **HTML 交互网页**——可点击、可动的效果
4. **解说视频**——3Blue1Brown 风格，沉浸式理解

ASD-STE100 是航空维修手册用的简化技术英语（约 900 个批准词汇、53 条写作规则）。Karpathy 本人建议日常用"80% of the way to ASD-STE100"，因为完整规范偏生硬。

## Workflow

1. **确认主题和层级**：用户用核心指令模板指定（"按第 [X] 层级把这件事讲清楚"），或直接说"用第 X 层讲 <主题>"。没指定层级时先问。
2. **按层级输出**：严格执行下表对应层级的规范，一次只做一层；用户要升级时再往上走。
3. **交付**：第 1–2 级直接在对话中输出；第 3 级生成独立 HTML 文件并附上；第 4 级输出视频脚本（含分镜与配音方案），不直接渲染视频——除非用户明确要求成片。

### 核心指令模板

> 请不要再用常规的文字来解释，请按照以下层级中的第 [X] 层级，把这件事给我讲清楚。

## 各层级规范

### 第一级：ASD-STE100 技术语言（最严谨、无歧义）

提示词：`请用 ASD-STE100 的标准技术英语来写。要求：一句话只说一件事；操作句不超过 20 个词；全部使用主动语态；确保没有歧义。`

- 适用：极度精准、避免误解的技术文档或流程说明。
- 变体：用户嫌生硬时改用 80% 模式——"Explain this in ASD-STE100, about 80% of the way"（短句、主动语态保留，措辞更自然）。
- 必须保留原文所有事实和限定词，不新增事实。

### 第二级：图表可视化（一眼看懂结构）

提示词：`请把这个复杂的流程画成一张思维导图/架构图。重点突出各个模块之间的关系和数据流向，让我一眼就能看清整体结构。`

- 适用：复杂工作流、代码依赖关系、组织架构。
- 优先用 Mermaid（对话内可渲染）；需要更精细排版时用 SVG。
- 图中标签文字准确性需复核，关系连线必须与事实一致。

### 第三级：HTML 交互网页（生动直观）

提示词：`请帮我生成一段 HTML 代码，做成一个能交互、带动画效果的网页。我可以通过点击按钮或者滑动条来动态查看不同的部分。`

- 适用：抽象概念、数据变化趋势、产品原型。
- 输出单个自包含 HTML 文件（内联 CSS/JS，无外部依赖），含选项卡、滑杆、动画等交互。
- 以文件形式交付给用户，不要只贴代码片段。

### 第四级：解说视频（沉浸式理解）

提示词：`请模仿 3Blue1Brown 的风格，制作一支讲解这个主题的解说视频脚本。如果需要配音，请提供本地免费 TTS 方案或 ElevenLabs API 推荐。`

- 适用：学习新知识、科普复杂理论，追求最佳理解体验。
- 输出：分镜脚本（场景/画面描述/旁白文案/时长）+ 配音方案（本地免费 TTS 或 ElevenLabs）。
- 默认只出脚本；用户明确要成片时再用 Manim + ffmpeg 渲染，并说明需要的时间和环境依赖。

## Output Contract

- 每一级只交付该级的格式，不混搭、不降级（除非用户要求）。
- 输出语言默认与用户一致（中文用户用中文讲解；第一级的 ASD-STE100 写作本身用英文，解释说明用中文）。
- 第 3 级必须交付可打开的文件；第 4 级必须包含可执行的配音方案。

## Operating Rules

1. 用户没指定层级时，先问层级再动手，不要默认从第一级开始全文输出。
2. 讲解对象是用户给的主题，不是 skill 本身——不要解释这个 skill。
3. 四个层级的提示词是用户定稿的原文，执行时保持原意，可按主题微调措辞。
4. 升级层级时沿用已确认的事实，不重新编造细节。
