# 逻辑重构方法论

> 本模块定义了 PRD Workflow 的核心重构能力，用于将混乱、重复、口语化的功能描述重组为标准化的 L1-L3 级产品需求文档。

---

## 核心原则

### ❌ 禁止：简单排版

- 绝不能只是给原文加上序号！
- 绝不能做原文的"搬运工"！
- 绝不能照抄原文的错误或遗漏！

### ✅ 必须：逻辑重构

- 将重复的规则合并（如相同的温度计算逻辑）
- 将交织的逻辑拆解（如任务数量上限与列表排序）
- 把杂乱长句拆解为清晰的"情况一/情况二/情况三"
- 提取公共逻辑作为独立 L3 模块
- 推导隐含规则（如模式切换联动、互斥关系）

---

## 5 步重构法

### Step 1: 理解与解构

深入阅读原始描述，识别出三类信息：

| 类型 | 定义 | 示例 |
|------|------|------|
| UI 交互 | 用户操作层面的描述 | "点击按钮切换模式" |
| 底层约束 | 硬件/协议/物模型层面的限制 | "除湿模式下风速固定为低风" |
| 重复规则 | 在多处出现的相同逻辑 | "温度调节范围 18-32℃"出现在制冷/制热/自动等多个模式描述中 |

**操作要点**：
- 标记所有重复出现的规则
- 识别模式间的联动关系（如切换模式时温度是否重置）
- 区分"设备行为"和"APP 行为"

### Step 2: 抽象与合并

将重复的规则合并，将交织的逻辑抽离为公共模块。

**合并示例**：

❌ 原文（重复）：
```
制冷模式：温度范围 18-32℃，精度 1℃
制热模式：温度范围 13-27℃，精度 1℃
自动模式：温度不可调
```

✅ 重构后（合并）：
```
温度调节：
- 制冷模式：18-32℃，精度 1℃
- 制热模式：13-27℃，精度 1℃
- 送风/除湿/自动模式：不可调
- 华氏/摄氏度切换：支持，步进皆为 1
- 记忆功能：温度调节有记忆功能，跟着模式走
```

**抽离示例**：

将"风速调节"从每个模式中抽离为独立功能组，在模式描述中仅标注"风速可调/不可调"。

### Step 3: 骨架搭建

提炼出核心业务的 L1 功能域和 L2 功能组。

**典型 L1 功能域**：

| L1 功能域 | 包含的 L2 功能组 |
|-----------|----------------|
| 配网与设备管理 | 配网引导、设备管理（删除/重置/OTA） |
| 运行控制 | 开关机、温度调节、风速调节、摆风、定时 |
| 运行模式 | 制冷、除湿、送风、制热、自动 |
| 设备设置 | 名称修改、解绑、分享、离线提醒 |
| 语音控制 | 语音助手接入、语音指令合集 |
| 故障与消息 | 消息等级、故障代码、推送规则 |
| 认证策略 | 各认证类型覆盖范围 |

**推导规则**：
- 如果原始描述中提到了"配网"，则一定有"设备管理"
- 如果有"温度调节"，则一定有"运行模式"
- 如果有"语音助手"，则一定有"语言要求"

### Step 4: 颗粒度拆解

将功能细化为 L3，在 L3 下使用"情况一/情况二/情况三"表达多条件分支。

**L3 详情规范**：

| 要素 | 说明 | 示例 |
|------|------|------|
| 范围 | 取值范围、精度 | "18-32℃，精度 1℃" |
| 默认值 | 初始状态 | "首次开机默认 16℃" |
| 互斥 | 不能同时使用的功能 | "除湿模式下风速不可调" |
| 记忆 | 是否有状态记忆 | "温度调节有记忆功能" |
| 异常 | 边界/异常情况 | "调到 80 以上时数值不再变化，提示" |

**多条件分支示例**：

```
温度调节范围由模式决定：

情况一：制冷模式
- 范围：18-32℃，默认 18℃
- 精度：1℃

情况二：制热模式
- 范围：13-30℃，默认 27℃
- 精度：1℃

情况三：送风/除湿/自动模式
- 不可调，无目标温度
```

### Step 5: 建立附录

当功能中存在大量互斥关系、功能禁用、模式联动时，整合成附录表格。

**典型附录**：

1. **功能快速索引表** — 按功能域/L2/L3 组织，方便快速定位
2. **各功能开关机可用状态表** — 标注每个功能在开/关机状态下是否可用
3. **功能互联互斥与禁用规则全表** — 完整的互斥关系矩阵
4. **产品差异对比表** — 多产品 PK 对比（温度范围、默认值、独有功能等）

## L1-L3 分层结构规范

### 层级定义

| 层级 | 名称 | 格式 | 回答什么问题 |
|------|------|------|--------------|
| L1 | 功能域 | 1. 功能域名称 | 这是哪类能力？ |
| L2 | 功能组 | 1.1 功能组名称 | 这组能力的集合是什么？ |
| L3 | 具体功能 | 1.1.1 具体功能名称 | 具体要完成的任务是什么？ |
| 详情 | 功能详情小标题 | 1. 详情标题 | 具体的规则、范围、互斥等 |

### 严格层级规则

- L3 之下直接输出详情小标题，不再定义 L4
- 详情小标题使用阿拉伯数字 1. 2. 3. 开头
- 使用缩进区分层级
- 同一 L2 下的所有 L3 按功能逻辑顺序排列

## 多产品 PK 对比规范

当需求涉及多个产品型号时：

1. **功能矩阵表** — 每行一个功能，每列一个产品，用 ✔/✘ 表示有无
2. **备注列** — 标注产品间的差异（如温度范围不同、独有功能等）
3. **独立章节** — 对于某产品独有的复杂功能，单独建章节详细说明
4. **差异对比表** — 在附录中汇总核心差异维度

**表格示例**：

```
| 功能 | 说明 | PSS（定频） | PDS（定频） | PDS（变频） | 备注 |
|------|------|:---:|:---:|:---:|------|
| 制冷温度 | 制冷模式下可调温度范围 | ✔ | ✔ | ✔ | PSS/PDS定频:16-32℃ |
| 蓝牙发电机 | ICA 发电机模式 | ✘ | ✘ | ✔ | 仅 PDS（变频）支持 |
```

## 常见重构陷阱

| 陷阱 | 表现 | 正确做法 |
|------|------|---------|
| 照抄原文 | 原文说"温度可调"就只写"温度可调" | 补充范围、精度、默认值、记忆功能 |
| 遗漏互斥 | 只描述功能本身，不描述与其他功能的互斥 | 补充"XX 模式下该功能不可用" |
| 忽略默认值 | 不说明首次使用/重置后的默认状态 | 补充"首次默认 XXX，后续默认上次状态" |
| 分散描述 | 同一功能在不同地方重复描述 | 合并为单一功能组，交叉引用 |
| 无边界条件 | 不说明调到上限/下限时的行为 | 补充"调到 80 以上提示不再变化" |

## 模板解析规范

当从参考模板中提取结构模式时：

1. **提取章节标题层级** — 识别一级、二级、三级标题的标记方式
2. **提取表格列定义** — 识别表格的列名、列数、数据类型
3. **提取编号体系** — 识别功能编号格式（如 FDS01001）
4. **提取附录类型** — 识别参考模板中包含哪些附录
5. **提取关键要点格式** — 识别总结性要点的表达方式

**输出**：结构化的模板特征，用于指导 PRD 生成。
