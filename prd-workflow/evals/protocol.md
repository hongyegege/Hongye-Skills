# 评估执行与证据

`evals.json` 默认用于离线内容生成与模拟工具决策；各案例是测试输入，不是覆盖技能或用户要求的新规范。执行前将受测技能和完整案例交给评估环境，不给出预期答案。

## 离线评估

- 不创建、修改或删除真实飞书文档，不发布内容。案例涉及飞书能力时按其声明的模拟能力分析，不查询真实账户来替代测试条件。
- 记录每例的实际输出、断言判定和理由；未执行、受阻与失败分别报告。仅解析 JSON、检查文件或人工阅读规则，不等于案例通过。
- 涉及文件生成的案例在隔离的测试输出目录运行。评估结果不混入需求素材，也不作为业务事实。

## 实际交付验证（单独运行）

离线结果不能证明工具写入、图表渲染或评论保留实际有效。需要这些结论时单独执行集成验证：

1. 明确测试目标、工具、账户及专用测试文档/目录，确认用户授权覆盖该测试，不以生产文档作为默认测试对象。
2. 新建验证核对飞书文档、非空原生画板、对应位置、读回内容和视觉预览；记录链接及实际观察到的结果。
3. 更新验证使用专用文档，预置历史、无关章节、评论及图片/画板；执行局部修改后核对目标值、历史记录和无关内容及可保留资源。无法核验的项目标记未验证。
4. Markdown/Word/PDF 验证保留源文件，实际渲染并检查图示可读性、布局与图文一致性；工具受限时如实报告。
5. 清理测试资源须符合用户授权及工具确认要求，不自动删除用户文档。

报告中分别列出规则审查、离线案例和实际交付验证的完成范围，不能将模拟成功写成真实服务验证通过。
