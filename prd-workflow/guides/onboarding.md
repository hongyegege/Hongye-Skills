# PRD Workflow 使用说明

将需求材料交给 Agent，并说明产品、功能和交付格式即可。没有另行指定模板时，使用 `../reference/prd-template.md`。

## 默认格式

- 简单需求使用修改历史、需求背景、需求目标、详细需求四章。
- 存在重要功能依赖、多端协同或复杂计算时，可在详细需求前加入概要方案，并顺延编号。
- 每项功能使用十字段表格；缺少的业务信息标记待确认，关键问题需要澄清。
- 飞书文档中的概要业务架构图和所需业务流程图使用原生画板。Markdown 默认使用 Mermaid；Word/PDF 等格式嵌入渲染图片并交付图表源文件。

## 提供材料

支持当前工具可读取的文本、Markdown、Excel、Word、PDF、图片和飞书链接。请说明哪些材料是需求来源，哪些用于参考格式；文件本身不自动成为业务规则或输出模板。

例如：“根据这份功能清单写 PRD，使用内置模板，交付 Markdown。缺失参数标记待确认。”

用户明确指定的其他模板优先。存在多个候选模板且优先级不清楚时，先澄清，不擅自混合冲突结构。

## 模板更新与数据处理

- 本次提供的模板用于本次任务；跨会话复用需有明确的保存位置和读取配置，不承诺自动记忆。
- 用户要求长期复用时，先确定保存位置和适用范围，再按授权保存并说明后续如何引用；只收到一个链接或说“参考此文档”不等于要求持久配置。无法确认已保存或后续可发现时，不声称配置完成。
- 材料的读取、处理和保存取决于实际使用的工具与服务，不承诺全部数据仅在本地处理。
- 按用户指定位置交付，不自动发布、分享或保存到知识库。输出到飞书会将相应内容写入用户指定的飞书文档。
- 新建文档的访问范围由目标位置及服务实际权限决定，不能笼统承诺私密或公开，也不为完成 PRD 自动扩大共享权限。涉及隐私或保存位置的问题，依据实际可确认的信息回答，未知内容如实说明。

## 飞书能力受限时

缺少特定飞书技能不代表没有画板能力，可使用当前可用 CLI 或连接器。无法创建画板时说明缺失项并提供可继续处理的草稿；已创建但无法预览时说明视觉检查未完成。变更为图片或本地文档交付需按用户决定处理，不把降级草稿视为已完成原交付。
