# PRD Workflow

根据需求材料生成清晰、可评审的产品需求文档。支持文本、Markdown、表格、文档、PDF、图片及可访问的飞书文档。选择当前环境可用的工具读取材料；不能访问时说明原因并请求可访问的替代材料。

## 模板选择

1. 用户本次明确指定的模板优先；其次使用用户明确指定的既有模板。
2. 否则读取本技能的 `reference/prd-template.md`，按照其中的 Agent 使用说明和完整模板生成。该模板适用于各类产品，无需按产品类型选择其他内置模板。
3. 内置模板默认采用修改历史、需求背景、需求目标、详细需求四章；存在重要功能依赖、多端协同或复杂计算时，默认在详细需求前增加概要方案，并顺延编号。用户明确要求省略或采用其他结构时遵从用户要求。使用内置模板时每项功能保留十字段表格，复杂规则可在对应功能小节就地展开并引用。

## 工作流程

1. 读取全部可访问材料，识别目标、功能、用户、业务约束与材料来源。
2. 根据所选模板整理需求；将同类内容归并，明确流程、状态、角色、参数、边界、异常与关联影响。复杂材料可参考 `assets/logic-reconstruct.md`；方法论、使用引导和评估案例均不得覆盖所选模板或引入无依据的业务规则。用户未指定其他模板时，以 `reference/prd-template.md` 为输出基准。
3. 关键问题阻碍方案时向用户澄清，同时完成不依赖答案的内容。其余缺失信息标注具体待确认事项，不编造事实或把建议写成已确认需求。
4. 根据所选模板生成完整 PRD；预测、算法、调度、分期或时序图表需求按需应用模板中的专项指引。核对目标、概要方案、详情、指标、文案、原型和状态处理的一致性，特别检查开启与就绪条件、指标边界、约束优先级、执行兜底及交付范围。
5. 先区分新建与更新已有 PRD。新建时按用户指定格式和位置创建；更新时先读取现有文档及相关资源，按请求范围在原文件/原文档修改，保留无关内容、修改历史及可保留的评论锚点和资源，不默认重建整篇或另存副本。用户明确要求全面按新模板重构时可调整整体结构，但不得丢弃原业务内容；工具限制可能损失评论或资源时先说明并确定处理方式。已有业务冲突不自行改成确定结论。记录实际变更并核对修改结果，返回原文档链接或更新后的文件。飞书工具不可用时可准备草稿，同时明确原交付未完成；不得把草稿视为用户已接受的替代交付。未经要求不自动发布、分享或沉淀到知识库。

原型、流程图、多产品差异对比等仅在实际需求需要时加入相应功能，不强制使用矩阵或另设章节。用户另行指定格式时以用户要求为准。

## 飞书文档中的架构图与业务流程图

- 输出为飞书文档且包含“概要方案”时，在其中使用飞书原生画板绘制整体业务架构图，说明主要参与方、系统/功能职责、数据或业务流向及依赖关系。
- 涉及业务流程图的部分，同样使用飞书原生画板，放在对应规则附近。根据已确认需求覆盖起点、前置校验、主路径、判断分支、异常与兜底、取消/返回、结束状态及跨端交互；未知分支标记待确认，不补造业务规则。
- 使用当前可用的飞书文档与画板能力；安装了 `lark-doc` 时读取其画板工作流，编辑时若有 `lark-whiteboard` 则读取其相关指引；没有这些技能时，查阅当前可用工具的说明完成同一原生画板要求，不能假定特定命令存在。更新时复用原画板。Mermaid、SVG 等可作为画板生成输入，最终须落为文档内有内容的原生画板，不以代码块、静态图片、外部链接或空白画板替代。
- 写入后读取文档核对画板引用及位置，并导出预览检查节点、连线、分支标签和文字可读性，同时核对图文一致性。多个独立流程可拆为多个画板。
- 按当前任务检查创建/更新画板、读回文档引用及视觉预览能力，不要求安装特定技能或工具品牌。只有部分能力可用时区分“未创建”“已创建但未完成校验”“已创建并校验”，逐图说明结果；不能因为写入请求成功就声称最终图表已验收。视觉检查可以使用工具实际支持的预览或截图。
- 若画板能力或权限不可用，继续完成可执行部分，明确报告缺失的画板及阻塞原因；需要替代形式时征求用户决定，不把替代形式视为已完成原生画板要求。

## 非飞书 PRD 的图表输出

- Markdown 默认在相应章节或功能规则附近使用 Mermaid 围栏代码块，置于表格外。整体业务架构采用分层、分组的 `flowchart`，展示用户、应用端、云端、设备端等实际参与方及流向；业务流程默认用 `flowchart TD`，展示起止、步骤、判断、异常和兜底。跨端交互按需用 `sequenceDiagram`，状态转换按需用 `stateDiagram-v2`。仅包含需求实际涉及的主体与规则。
- 图表采用简洁统一配色、清晰分组和带说明的连线，突出主流程并区分异常分支；颜色不作为唯一含义载体。图中文字与正文口径一致，使用说明性的节点和分支标签。
- Word、PDF 或不支持 Mermaid 的阅读环境中，将图表渲染为 SVG 或 PNG 并嵌入；按目标格式的兼容性选择 SVG 或 PNG，同时交付对应 Mermaid 源文件以便修改。Markdown 中的 Mermaid 源码保留，必要时同时提供图片预览。
- 渲染交付前检查语法与图像，核对文字、连线、分组、分支完整性及页面可读性；渲染能力受限时明确说明，不声称已完成图片交付。用户明确指定其他格式或样式时遵循用户要求。

## 技能评估

需要测试技能时，按 `evals/protocol.md` 区分离线模拟与实际交付验证，案例见 `evals/evals.json`。普通生成 PRD 无需加载评估文件；模拟结果不能代替真实工具与图表验证。
