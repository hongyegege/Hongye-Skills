# PRD Workflow — 产品需求文档端到端生成工作流

## 技能简介

本 Skill 是一个**端到端的 PRD 生成编排引擎**，覆盖从需求材料输入到飞书文档产出的完整链路：

1. **多格式输入** — 支持 Excel / Word / PDF / 图片 / Markdown / 飞书文档 / 纯文本
2. **模板参照** — 优先使用用户提供的参考材料，降级使用内置通用模板
3. **需求确认** — 执行前先复述理解，避免方向错误
4. **逻辑重构** — 深度去重、归纳、推导场景、提取公共规则（内置）
5. **标准化输出** — L1-L3 分层结构 + 功能矩阵 + 附录，统一格式

**开箱即用**：所有核心能力已内置，无需额外安装其他 Skill。

> **注**：本 Skill 是 prd-writer 的端到端编排增强版，已内置其全部逻辑重构能力。
> 后续将以本 Skill 为核心，prd-writer 不再维护。

---

## 核心原则（铁律）

### ❌ 禁止
- 简单排版（给原文加序号 ≠ 逻辑重构）
- 搬运原文（绝不做"复制粘贴工"）
- 编造不存在的模板或依赖
- 暴露用户私有路径信息

### ✅ 必须
- 先自检环境，再执行流程
- 先确认需求理解，再动手生成
- 合并同类项、提取差异、推导公共规则
- 输出物遵循 L1-L3 分层结构
- 创建文档后必须返回可点击链接

---

## 执行流程（8 步编排）

```
Step 0: 环境自检 → Step 1: 文件解析 → Step 2: 模板检索
    ↓
Step 3: 需求确认 → Step 4: 模板解析 → Step 5: 逻辑重构
    ↓
Step 6: PRD 生成 → Step 7: 创建文档 → Step 8: 知识沉淀（可选）
```

---

### Step 0: 环境自检

执行前检查以下依赖，根据结果选择执行路径：

| 依赖项 | 检查方式 | 缺失后果 | 降级方案 |
|--------|---------|---------|---------|
| 文件解析能力 | `python3 -c "import pandas"` | 无法解析 Excel | 要求用户提供文本或其他可解析格式 |
| 内置 PRD 模板 | 检查本 Skill 目录下 `reference/PRD-template.md` | 无格式参照 | 使用纯文本 L1-L3 结构输出 |
| PDF 解析能力 | 检查 pdf 工具可用性 | 无法解析 PDF | 提示用户转换格式或提供文本 |
| 文档拉取能力 | 检查 feishu_fetch_doc 可用性 | 无法拉取飞书文档 | 要求用户导出为本地文件 |

**自检逻辑**：
1. 遍历依赖清单，标记 ✅/⚠️/❌
2. 核心依赖（逻辑重构能力）始终可用（内置于本 Skill）
3. 可选依赖缺失 → 自动降级 + 告知用户当前状态
4. **永远不要假装依赖存在，永远不要编造不存在的模板**

---

### Step 1: 多格式输入解析

| 输入格式 | 解析方式 | 工具 |
|---------|---------|------|
| Excel (.xlsx/.xls) | 解析所有 Sheet，提取表头 + 样本数据 | exec + pandas |
| Word (.docx) | 提取文本内容 | exec + python-docx |
| PDF (.pdf) | PDF 文本提取 | pdf 工具 |
| 图片 (.png/.jpg) | OCR 识别图片中的文字 | image 工具 |
| Markdown (.md) | 直接读取 | read |
| 飞书文档 URL | 拉取飞书云文档内容 | feishu_fetch_doc |
| 纯文本 | 直接使用用户输入 | 无 |

**解析策略**：
1. 识别文件类型 → 选择对应解析器
2. 解析失败 → 提示用户更换格式或手动提供文本
3. 多文件输入 → 合并解析，按来源标注

---

### Step 2: 知识库/参考模板检索

**检索优先级**（从高到低）：

1. **用户本次提供的参考材料** — 用户随需求一起发送的文件/文档
2. **用户已配置的自定义知识库** — 用户之前提供的参考模板（如存储在本地目录）
3. **内置通用 PRD 模板** — `reference/PRD-template.md`（保底方案）

#### 无自定义知识库时的引导流程

当检测到用户未提供自定义参考模板时，执行引导：

---

📖 **检测到您尚未配置个人参考知识库**

当前将使用内置通用 PRD 模板生成文档。如需更精准的风格匹配，
建议您提供参考材料作为生成参照。支持以下格式：

1. **飞书文档链接** → 直接发给我飞书文档 URL
2. **本地文件** → 发送 .md / .docx / .pdf / .xlsx 文件
3. **纯文本** → 直接粘贴 PRD 模板内容
4. **图片** → 发送包含 PRD 格式的截图

您可以随时提供参考材料，我会在下次生成时优先使用您的模板。

---

**引导触发时机**：
- 首次使用本 Skill 时
- 用户未提供任何参考材料时
- 用户主动询问"如何配置模板"时

---

### Step 3: 需求理解与确认

**智能判断策略**：

| 场景 | 判断标准 | 行为 |
|------|---------|------|
| **需求明确** | 产品名清晰、输入材料完整、无歧义 | 简要确认后即可执行，无需等待用户回复 |
| **需求模糊** | 产品名不明、材料不完整、存在歧义 | 必须向用户复述理解，等待确认后再执行 |
| **用户明确要求跳过** | 用户说"直接生成"/"不用确认" | 跳过确认步骤，直接执行 |

**确认格式**（仅在需求模糊时使用）：

```
👀 我理解您的需求：
- 输入材料：[文件格式]，[文件名称/描述]
- 目标产品：[产品名称]
- PRD 类型：设备导入 / 平台功能迭代 / 大型平台建设项目
- 参考模板：[用户提供的模板 / 内置通用模板]
- 特殊要求：[如有]

这样理解对吗？确认后我将开始生成 PRD。
```

**原则**：确认是为了防止方向错误，不是为了增加不必要的交互成本。需求明确时，高效执行优先。

---

### Step 4: 模板解析与结构提取

从参考模板中提取：
1. **章节结构** — 产品概述 → 功能矩阵 → 附录 → 关键要点
2. **表格格式** — PK 产品对比列、✔ 矩阵、备注列
3. **附录规范** — 功能快速索引表、开关机状态表、互斥规则表

> 详见 `assets/logic-reconstruct.md` 中的模板解析规范。

---

### Step 5: 逻辑重构（核心能力）

> 完整逻辑重构方法论见 `assets/logic-reconstruct.md`

**5 步重构法**：

| 步骤 | 操作 | 示例 |
|------|------|------|
| 1. 理解与解构 | 识别 UI 交互 / 底层约束 / 重复规则 | 识别温度逻辑在多处重复 |
| 2. 抽象与合并 | 合并同类项，抽离公共模块 | 3 个产品共有的配网功能合并 |
| 3. 骨架搭建 | 提炼 L1 功能域和 L2 功能组 | 配网 / 控制 / 模式 / 语音 |
| 4. 颗粒度拆解 | L3 具体功能 + 多条件分支 | 制冷温度范围 / 制热温度范围 |
| 5. 建立附录 | 互斥关系矩阵、禁用规则汇总 | 功能互联互斥表 |

**关键输出**：
- 合并后的功能矩阵（多产品用 ✔ 矩阵对比）
- 差异项单独标注（备注列或独立章节）
- 公共规则提取为独立模块

---

### Step 6: PRD 文档生成

按模板结构组装 PRD 内容：
1. **产品概述** — 表格形式
2. **功能矩阵** — 按功能域分章节，每章含功能对比表格
3. **互联互斥规则** — 表格或列表
4. **故障及消息推送** — 等级 + 事件表
5. **认证策略** — 多产品对比表
6. **附录** — 快速索引、开关机状态、互斥规则、差异对比
7. **关键要点** — 提炼核心注意事项

**格式要求**：
- 使用 Markdown 表格（飞书兼容）
- PK 产品对比使用 ✔/✘ 矩阵
- 差异写在备注列
- L1-L3 分层结构清晰

---

### Step 7: 飞书文档创建

```
feishu_create_doc:
  - title: [PRD 标题]
  - folder_token: [用户指定或默认文件夹]
  - markdown: [完整 PRD 内容]
```

**必须返回可点击文档链接。**

---

### Step 8: 知识沉淀（可选）

提示用户是否生成蒸馏摘要：

```
📝 PRD 已创建完成。是否需要生成一份蒸馏摘要存入本地知识库？
蒸馏摘要将提取 PRD 的核心结构和关键信息，供后续 PRD 生成时作为参考模板使用。
```

如用户确认：
- 生成精简版摘要（产品概述 + 功能域结构 + 关键差异点）
- 提示用户保存位置或自动存入本地知识库目录
